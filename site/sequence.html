03 / Proposed delivery sequence

At-least-once delivery needs explicit duplicate handling

The retry reuses the event ID and enriched payload. A lost response or a worker crash can repeat a delivery even when the endpoint already accepted it. Recipient deduplication is part of the integration contract.

Recovery contract: processing is idempotent by tenant and event ID. Work leases expire after crashes. Rescheduling is durable before releasing the current claim; already-recorded success suppresses further attempts. Permanent failures and exhausted retries enter controlled recovery, not an endless loop. Delivery order is not guaranteed by this proposal.
